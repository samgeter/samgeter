# GitHub profile cleanup checklist

Use this file as a one-time checklist. It is not intended to be published in the `samgeter` profile repository.

## 1. Publish the profile README

1. Create a **public** repository named exactly `samgeter`.
2. Add `README.md` from this folder to its default branch.
3. GitHub will automatically render it above the pinned repositories on the profile.

## 2. Complete the profile sidebar

Suggested values:

- **Name:** Use your full professional name, not only the username.
- **Bio:** `Frontend developer building thoughtful web products with React and TypeScript.`
- **Location:** Add your city and country if you are comfortable sharing them.
- **Website:** Add a portfolio or the strongest live project once it is ready.
- **Social link:** Add LinkedIn or another professional channel you actively maintain.
- **Available for hire:** Enable this only if it matches your current goals.

Use a clear headshot or a deliberate personal logo. The current abstract avatar does not help visitors recognize you.

## 3. Curate the pinned repositories

Recommended order:

1. `kuri-mothers-health`
2. `RootcozUI`
3. `Yuba-invitation-email`
4. `grocery-todo-list` only after its README and live demo are improved

Unpin `Yuba-Google-Calendar-API-Test` while it is empty. Four strong projects look more intentional than six incomplete cards.

## 4. Improve repository names and descriptions

Use consistent lowercase kebab-case for future repository names. Renaming existing repositories is optional because GitHub redirects old links.

Suggested descriptions:

- **kuri-mothers-health:** `Responsive maternal-health platform for natural lactation products, expert guidance, and community support.`
- **RootcozUI:** `Responsive React landing page for Rootcoz, built with Vite and Tailwind CSS.`
- **Yuba-invitation-email:** `Reusable Node.js invitation-email service with HTML templates and Nodemailer.`
- **grocery-todo-list:** `Lightweight grocery-list app built with vanilla JavaScript, HTML, and CSS.`

Suggested topics:

- **kuri-mothers-health:** `react`, `typescript`, `vite`, `tailwindcss`, `shadcn-ui`, `maternal-health`
- **RootcozUI:** `react`, `vite`, `tailwindcss`, `responsive-design`, `landing-page`
- **Yuba-invitation-email:** `nodejs`, `nodemailer`, `email-templates`, `smtp`
- **grocery-todo-list:** `javascript`, `html`, `css`, `todo-app`

## 5. Make each pinned project recruiter-ready

Every pinned repository should have:

- A one-sentence value proposition at the top of its README
- A screenshot or short demo GIF
- A live demo link when possible
- A short feature list
- Clear local setup instructions
- A technology list
- A brief "What I learned" or "Technical decisions" section
- A license, if the code is intended for reuse
- A meaningful repository description and topics

Priority fixes:

- Replace the generated `kuri-mothers-health` README (`Welcome to your Lovable project`) with real project documentation.
- Add a README to `RootcozUI`.
- Add a README and demo link to `grocery-todo-list`.
- Replace the real Gmail address shown in the public `Yuba-invitation-email` README example with a neutral value such as `your-email@gmail.com`.
- Archive or make private any abandoned test repository that does not represent your current skill level.

## 6. Keep the presentation credible

- Avoid animated typing banners, trophy walls, visitor counters, and large collections of statistics cards.
- Keep badges limited to technologies you have actually used.
- Show two or three well-explained projects before adding more visual decoration.
- Review the profile every few months so "currently learning" and featured work stay accurate.
